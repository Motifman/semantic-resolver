# 意味精度と費用の評価計画

初版の模擬 HTTP テストは接続契約を確認するものであり、意味の正しさを証明しない。
主モデルの出力を正式値へ変えられた件数だけを「成功率」として報告しない。

## 比較条件

1. 主モデルと、完全一致・明示的な補正のみ
2. 主モデルに動的候補を制約として与える方式
3. 未解決の出力だけを Jev で意味解決する方式
4. 未解決の出力を別の小型判断器で解決する方式
5. 主モデルを挟まず、状態から Jev が候補を直接選択する方式

比較時は同じ説明付き候補と対応なしの選択肢を使う。主モデルの版、接続先、
プロンプト、候補、採用基準、判断器の版を記録する。

## データ

正しい対応先のある言い換え、話題が近いだけの別操作、候補なし、曖昧な表現、
対象を取り違えた表現、候補は正しいが実行条件を満たさない事例を含める。
日本語・英語、未知のシナリオ、350M 級モデルの実出力を分けて報告する。
閾値の調整に使うデータと最終評価データを分離する。

正解はモデルの採用結果から逆算しない。許される対応先の集合または対応なしを、
元の意図と候補説明に基づいて独立に確認する。

## 指標

- 採用した解決の正解率と、誤補正の件数
- 正解が存在する事例のうち、正しく解決した割合
- 対応なし・曖昧・閾値未達・障害の件数
- 意図した操作が実際に成立した割合
- 一要求の待ち時間の中央値と95パーセンタイル、総費用
- 主モデルのキャッシュ読み込みトークン、書き込みトークン、非キャッシュ入力
- 主モデルと判断器を合計した、正しく完了した一件あたりの費用

既存 llm-rpg の実験索引にある「採用した件数」は正解率ではない。
元データと正解の独立確認が揃ってから、新しい評価へ取り込む。
